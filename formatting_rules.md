# Formatting Rules

These formatting rules apply to all customer-facing outputs (emails, Salesforce artifacts, RFX answers, etc.).

## Plain Text Only - NO Markdown

- **NEVER use markdown syntax** in customer-facing content:
  - No **bold**
  - No *italic*
  - No `code`
  - No ### headers
  - No > blockquotes
  - No [links](url) - write out URLs directly

- **Use only:**
  - Spaces
  - Tabs
  - New lines
  - Regular hyphens (-)
  - Regular text

## Critical: No Long Dashes

- **NEVER use long dashes (em dashes —)** - they look AI-generated
- Always use regular hyphens (-) instead
- Example:
  - ❌ "This is important — very important"
  - ✅ "This is important - very important"

## Structure

- Use blank lines to separate sections
- Use dashes (-) for top-level bullet points
- Use tabs for sub-items under bullets
- Use clear section labels (plain text, not headers)

## Email-Specific Rules

- No signature (Gmail adds it automatically)
- No greeting unless it flows naturally
- Brief, clear, technical tone
- Link-centric: provide URLs, don't write long explanations

## Salesforce Artifacts-Specific Rules

- Three labeled sections: USE CASE:, RISKS:, NOTES:
- Each label on its own line
- Use only dashes and tabs for structure (no markdown)
- Plain text throughout

## General Voice

- Concise and clear
- Technical but accessible
- No fluff or filler
- Focus on "why" not just "what"
